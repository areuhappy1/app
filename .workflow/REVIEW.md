# 검수 결과

2026-09-26 · 구현 담당자의 자체 검수. 별도 에이전트/외부 검수자의 승인을 받은 문서가 아님.

## 통과
- 기존 파서 7개, 지역/알림/캘린더 로직 7개, 앱 런타임 4개: 총 18개 통과.
- 실제 로컬 브라우저: 주문자/수령인 분리, 배송지 지역 자동 채움, 등록 후 이름·지역 표시, 지역 검색, 카드 클릭/Enter 상세보기, 상세→수정→지역 저장.
- 실제 로컬 브라우저: 10분 미루기 후 새로고침 유지, 다시 표시, 알림 확인 후에도 주문 접수 상태 유지.
- 실제 로컬 브라우저: 날짜를 과거로 수정하면 지연 알림 재생성, 기본 목록에서 지난 미완료 주문 표시, 완료 후 알림 제거, 전체 목록에서 완료 주문 상세 조회.
- 런타임 모의 검증: 자동 수집 메시지 알림에서 해당 입력 카드로 연결, 기기 알림 중복 방지 및 주문별 이동 주소, 권한 거부/미지원 시 앱 내 알림 유지, 자동 권한 요청 없음.
- 브라우저 오류 로그 없음. 기기 알림 본문에 이름/주소를 노출하지 않음.
- 캘린더: UTC 시간, 한글 UTF-8 줄 접기, 특수문자 이스케이프, 알림 시간, 날짜·시간 미정 처리 테스트 통과.

## 검수 중 수정
- 자동 수집 알림에서 단일 DOM 요소에 find를 호출하던 연결 오류를 수정하고 런타임 회귀 테스트 추가.
- 작은 화면에서 상세보기 닫기 버튼이 보이도록 제목을 고정.
- 서비스워커 갱신 시 다른 앱/공유 대기 캐시를 삭제하지 않도록 캐시 범위를 제한.

## 남아 있는 제약 및 검증 범위
- 앱 종료 상태의 서버 푸시는 구현하지 않음. 앱 내 문구와 README에 명시. 실행 중 브라우저 알림 및 사용자가 캘린더에 가져온 수령 일정 알림 제공.
- 실제 휴대폰 OS 알림 수신과 실제 운영 서버 연동은 검증하지 않음. 브라우저 알림 API는 모의 런타임으로 확인.
- 캘린더 버튼의 생성 실행/안내 표시는 브라우저에서 확인했으나 내장 브라우저의 다운로드 이벤트는 시간 초과. 실제 외부 캘린더 가져오기와 알림 발생은 검증하지 않음.
- 캘린더의 기존 일정은 주문 수정/취소와 자동 동기화되지 않음.
- 모든 브라우저 검증은 로컬 테스트 주문으로 수행. 운영 주문 데이터 변경 및 운영 배포 없음.
